# RetailVision 360 — REST API Reference

The backend provides a typed FastAPI interface with automated OpenAPI specifications accessible at `/docs` and `/redoc`.

Base URL: `http://localhost:8000/api`

---

## 1. System & Health

### `GET /health`
Returns system status, active database dialect, and uptime.
- **Response**: `{"status": "healthy", "service": "RetailVision 360 API"}`

### `GET /system/status`
Returns readiness flags for Computer Vision models, SQLite persistence, and Gemini LLM.
- **Response**:
```json
{
  "backend": "healthy",
  "database": "connected",
  "vision_model": "yolov8n",
  "device": "cpu",
  "gemini_status": "ready",
  "gemini_model": "gemini-2.5-flash",
  "demo_mode": true
}
```

## 3. Shelf Auditing

### `POST /shelf-audits`
Multipart form upload of a shelf photograph to run genuine inference, create persistent audit records, calculate occupancy, generate diagnoses, and spawn operational tasks.
- **Parameters**:
  - `file`: Image file (JPEG, PNG, max 10MB)
  - `store_id`: Store identifier (e.g. `store-001`)
  - `aisle`: Aisle string (e.g. `Aisle 4 - Snacks & Beverages`)
  - `shelf_id`: Shelf code (e.g. `Shelf-B2`)
  - `planogram_id`: Optional associated planogram ID
  - `target_facing_count`: Expected product facing target (default: `8`)
- **Response**: Full `ShelfAudit` object with detection list, occupancy percentage, and generated diagnoses.

### `GET /shelf-audits`
List all historical shelf audits with query filters (`store_id`, `limit`, `offset`).

### `GET /shelf-audits/{audit_id}`
Retrieve a specific audit record with associated detections, diagnoses, and task references.

### `GET /shelf-audits/{audit_id}/annotated-image`
Streams the bounding-box annotated output image generated by OpenCV/YOLOv8.

## 4. Planograms

### `GET /planograms`
Retrieve all configured shelf layout planograms.

### `POST /planograms`
Create a new store planogram with structured grid positions and expected product IDs.

### `POST /planograms/{planogram_id}/compare`
Multipart upload an observed shelf image to perform spatial facing comparison against the configured layout.
- **Response**:
```json
{
  "planogram_id": "plano-001",
  "name": "Beverages & Cold Drinks Layout",
  "expected_facings": 6,
  "observed_facings": 2,
  "compliance_percentage": 33.3,
  "discrepancies": [
    {
      "type": "EMPTY_SLOT",
      "slot_row": 1,
      "slot_col": 3,
      "expected_product_id": "prod-002",
      "message": "Expected product prod-002 missing at row 1, col 3"
    }
  ]
}
```

## 5. Products & Inventory

### `GET /products`
List all retail SKUs in the catalog.
- **Query params**: `category`, `search`, `limit`.

### `POST /products`
Add a new SKU with barcode, unit price, reference image, expected shelf quantity, and minimum restock threshold.

### `GET /inventory`
Retrieve current inventory records, including recorded shelf quantity, backroom stock, daily sales rate, and data source.

### `POST /inventory/updates`
Submit manual inventory cycle counts or simulated ERP synchronization feeds.

## 6. Product Recognition

### `POST /products/recognize`
Multipart upload a cropped packaging image to run 3D HSV histogram and ORB keypoint matching against catalog reference images.
- **Response**:
```json
{
  "status": "success",
  "best_match": {
    "product_id": "prod-001",
    "name": "Organic Oat Milk 1L",
    "confidence": 0.88,
    "verdict": "MATCHED"
  },
  "candidates": [
    {"product_id": "prod-001", "name": "Organic Oat Milk 1L", "score": 0.88},
    {"product_id": "prod-005", "name": "Cold Brew Coffee 330ml", "score": 0.42}
  ]
}
```

## 7. Tasks, Verification & Priority Queue

### `GET /tasks`
Retrieve operational tasks with status filters (`OPEN`, `IN_PROGRESS`, `RESOLVED`, `FAILED_NEEDS_REVIEW`).

### `GET /priority-queue`
Returns tasks sorted by deterministic Priority Score, exposing transparent score breakdown components.

### `PATCH /tasks/{task_id}`
Update employee assignment, workflow status, or add review notes.

### `POST /tasks/{task_id}/verify`
Multipart upload a post-remediation shelf image. Runs CV detection and updates task to `RESOLVED` if `after_count >= target_facing_count`.

---

## 8. Checkout Discrepancy Monitoring

### `GET /checkout/sessions`
List monitored POS checkout sessions.

### `POST /checkout/sessions`
Record a POS transaction with line items and optional sensor/scale measurements.

### `POST /checkout/sessions/{session_id}/reconcile`
Executes automated discrepancy rules comparing item counts and weight variances to flag un-scanned items.

---

## 9. Store Analytics & Dwell Time

### `GET /analytics/zones`
Retrieve activity metrics, customer counts, and average dwell times across store zones.

### `GET /analytics/heatmap`
Returns aggregated 2D coordinates representing customer movement and congestion intensity.

---

## 10. Gemini AI Copilot

### `GET /chat/status`
Check Gemini API availability, active model ID, and grounding connectivity.

### `POST /chat/conversations`
Initialize a new chat conversation thread.

### `POST /chat/conversations/{conversation_id}/messages`
Send a user prompt to the Gemini copilot.
- **Payload**: `{"content": "Which shelves require immediate restocking?"}`
- **Response**: Grounded response answering directly from SQLite records, with optional structured action links.

---

## 11. Settings & Demo Data

### `POST /settings/reset-demo`
Idempotently resets the SQLite database to the canonical demo state without deleting user uploads or code files.
